# Великая Отечественная война в контексте Второй мировой войны

Многостраничный образовательный сайт по разделу III «БССР в годы Второй мировой и Великой
Отечественной войн» учебного пособия «История Беларуси, 1917 г. — начало XXI в.» (9 класс, § 11–16).

**Хаб** (главная страница-навигатор) + **8 тематических мини-сайтов**: интерактивная карта,
хронология, ИИ-конспект, личности с реальными портретами, галерея фото и документов, викторина.

## 🚀 Быстрый старт в Visual Studio Code

> Важно: это не набор HTML-файлов, а проект на Next.js. Если просто открыть `.tsx`/`.html` в браузере,
> будет пустая страница. Сайт нужно либо **запустить** (`npm run dev`), либо **собрать** в статические
> файлы (`npm run build:static`) и открыть папку `out/`.

Нужны [Node.js 20+](https://nodejs.org) и [VS Code](https://code.visualstudio.com).

1. Откройте папку проекта в VS Code (`File → Open Folder`). VS Code предложит установить
   рекомендуемые расширения (ESLint, Prettier, Tailwind, **Live Server**) — согласитесь.
2. Откройте терминал (`Ctrl + ~`) и выполните:

```bash
npm install
```

### Вариант А — просто посмотреть сайт (без сервера и базы данных)

```bash
npm run build:static      # собирает статический сайт в папку out/
npm run preview:static    # открывает http://localhost:4173
```

Или через **Live Server**: после `npm run build:static` нажмите «Go Live» в правом нижнем углу
VS Code — настройки проекта уже указывают Live Server на папку `out/`.

Те же команды доступны через `Terminal → Run Task…` (задачи 1–4) и через `Run → Start Debugging`.

### Вариант Б — режим разработки (с «горячей» перезагрузкой)

```bash
npm run dev               # http://localhost:3000
```

База данных **не обязательна**: без неё сайт работает полностью, а серверные функции
(общая статистика класса, синхронизация прогресса, ИИ-конспект) мягко отключаются —
прогресс и результаты викторин хранятся в браузере, конспекты показываются подготовленные.

### Вариант В — полный режим (PostgreSQL + ИИ)

```bash
cp .env.example .env      # укажите DATABASE_URL и при желании OPENAI_API_KEY
npm run db:push           # создаёт таблицы
npm run dev
```

### Если не отображаются картинки

Картинки подключены так, чтобы не ломаться ни в какой среде:

- **относительные пути** (`./images/…`, `../../images/…`) — не зависят от подпапки GitHub Pages
  и от корня Live Server;
- **запасные источники** — если локального файла нет, фото подгружается с Wikimedia Commons,
  а вместо недоступной обложки показывается реальная фотография по теме;
- если не загрузилось ничего — аккуратная заглушка вместо «битой» рамки.

Что проверить, если картинок всё же нет:

1. `npm run images:fix` — проверяет все файлы в `public/images` и докачивает отсутствующие или
   повреждённые (такое бывает, если при копировании проекта потерялись бинарные файлы).
2. Пересоберите статическую версию: `npm run build:static` (старая папка `out/` удаляется
   автоматически) и откройте сайт через `npm run preview:static` или «Go Live».
3. Не открывайте `out/index.html` двойным щелчком (`file://`) — нужен локальный сервер. Если
   стили не загрузились, вверху страницы появится подсказка с этими же командами.
4. При работе с git файл `.gitattributes` помечает картинки как бинарные — не удаляйте его.

## 📱 Адаптивность

Сайт проверен на ширинах 375 px (телефон), 768 px (планшет), 1280 px (десктоп) и в альбомной
ориентации телефона — без горизонтальной прокрутки.

- **Шапка темы:** на телефоне и планшете — две строки («‹ Темы», название, переключатель темы и
  прокручиваемая лента разделов, активный раздел сам подъезжает в центр); на десктопе — одна.
- **Хаб:** фильтры по тегам на телефоне листаются горизонтально; сетка тем — 1 / 2 / 3 колонки.
- **Карта:** всегда показывает всю Беларусь; на сенсорных экранах один палец прокручивает
  страницу, два — двигают и масштабируют карту (режим «одним пальцем» включается кнопкой);
  подписи областей и рек скрываются на мелком масштабе; список точек — под картой.
- **Кнопки и чипы** на сенсорных экранах имеют зону нажатия не меньше ~40 px; кнопка «Наверх»
  учитывает «чёлку»/жестовую панель (`safe-area-inset`).
- Все правила собраны в конце `src/app/globals.css` в блоке «Адаптивность».

## 📦 Публикация на GitHub

1. Создайте репозиторий на GitHub (например, `Bagration_sait_`) и отправьте проект:

```bash
git init
git add .
git commit -m "Образовательный сайт по истории ВОВ в Беларуси"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

   Файл `.env` с секретами в репозиторий не попадёт (он в `.gitignore`); шаблон — `.env.example`.

2. В настройках репозитория: **Settings → Pages → Build and deployment → Source: «GitHub Actions»**.

3. Готово. При каждом push в `main` workflow `.github/workflows/deploy-pages.yml` соберёт
   статическую версию и опубликует её по адресу
   `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`. Подпапка (`basePath`) подставляется
   автоматически из имени репозитория; для репозитория `ВАШ_ЛОГИН.github.io` сайт будет в корне.

На GitHub Pages работают все страницы, карты (без интернета — векторная схема, с интернетом —
онлайн-подложка по кнопке), хронологии, галереи, викторины и локальные конспекты; личный прогресс
хранится в браузере. Серверные функции (общая статистика, ИИ-генерация) доступны только при
развёртывании с сервером — например, на **Vercel**: импортируйте репозиторий, задайте
`DATABASE_URL` (Neon / Supabase / Vercel Postgres) и `OPENAI_API_KEY`, выполните `npm run db:push`.

Workflow `ci.yml` проверяет типы и обе сборки при pull request.

## Технологии

- Next.js (App Router), React, TypeScript; Tailwind CSS 4 + дизайн-система на CSS-переменных
- Leaflet — карты (векторная схема Беларуси офлайн + онлайн-тайлы OSM/CARTO по кнопке)
- PostgreSQL + Drizzle ORM — опционально (результаты викторин, прогресс, кэш ИИ-конспектов)

## Структура проекта

```
src/
  app/
    page.tsx                 ← хаб (статическая страница)
    topics/page.tsx          ← список тем
    topics/[slug]/page.tsx   ← шаблон страницы темы (общий для всех тем)
    api/                     ← серверные маршруты (в статической сборке отключаются)
    globals.css              ← дизайн-система, светлая/тёмная тема, стили карты
  data/
    types.ts                 ← типы данных темы
    topics/topic-0X-*.ts     ← контент каждой темы (текст, карта, хронология, викторина…)
    topics/index.ts          ← реестр тем
    photos.ts, photo-manifest.json ← реальные фото и портреты (Wikimedia Commons)
  components/                ← карта, таймлайн, викторина, галерея, ИИ-конспект, хаб…
  lib/paths.ts, useAsset.ts  ← относительные пути к картинкам (работают в любой подпапке)
  components/SmartImage.tsx  ← изображение с запасными источниками и заглушкой
  db/                        ← схема и подключение PostgreSQL (необязательно)
public/images/               ← иллюстрации и фото
public/geo/                  ← границы Беларуси (geoBoundaries) и реки (Natural Earth)
scripts/                     ← статическая сборка, локальный сервер, загрузка и проверка фото
.vscode/                     ← настройки, задачи и конфигурации запуска для VS Code
.github/workflows/           ← публикация на GitHub Pages и CI
```

## Как добавить новую тему

1. Скопируйте любой файл `src/data/topics/topic-XX-*.ts`, заполните объект `Topic`
   (hero, intro, map.points, timeline, summary, persons, gallery, quiz).
2. Импортируйте его в `src/data/topics/index.ts` и добавьте в массив `topics`.
3. Положите обложку в `public/images/topics/`. Страница появится по адресу `/topics/<slug>/`.

## Конспект через ИИ

- **Вариант А (API):** при заданном `OPENAI_API_KEY` маршрут `/api/summary` отправляет текст темы в
  модель (по умолчанию `gpt-4o-mini`; настраивается `OPENAI_MODEL`, `OPENAI_BASE_URL`), результат
  кэшируется в БД. Ключ хранится только на сервере и не попадает в браузер.
- **Вариант Б (fallback):** без ключа, без сервера или при ошибке показывается заранее подготовленный
  конспект (`summary.short / medium / full` в данных темы). Кнопки «Сократить / Расширить» работают
  одинаково в обоих режимах.

## Фотографии и портреты

Портреты персон и исторические фото загружены с Wikimedia Commons скриптами
`scripts/fetch-wiki-photos.mjs` и `scripts/fetch-wiki-photos-pass2.mjs` (только файлы, размещённые на
Commons, т. е. со свободными лицензиями; автор и лицензия сохраняются в `src/data/photo-manifest.json`
и выводятся в подписях). Сопоставление «персона → фото» и подписи к фотографиям — в `src/data/photos.ts`.

## Источники

Содержание тем соответствует учебному пособию «История Беларуси, 1917 г. — начало XXI в.»
(9 класс; С. В. Панов, В. Н. Сидорцов, В. М. Фомин), раздел III, § 11–16. Изображения, подписанные
как «художественная реконструкция», созданы специально для сайта в учебных целях; исторические
фотографии и портреты — Wikimedia Commons, современные фото мемориалов — Wikimedia Commons и Pexels
(авторы указаны в подписях). Границы — geoBoundaries (CC BY 4.0), реки — Natural Earth (public domain).
